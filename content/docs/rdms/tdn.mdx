## Overview

[Taidan] is the [out-of-box experience] for Ultramarine 42 and newer.
It's built with Rust and [Slint]. Versions before 1.0 used GTK4 and [libhelium].

Taidan is standalone from Readymade, meaning you can combine it with any installer, or even lack thereof (in the case of preinstalled images).

## History

Driver installation was previously handled by [Stellar], "a quick-and-dirty GUI post-install
menu […] meant to be used for Ultramarine Linux 39's Anaconda post-install menu"[^1].

We messed this up, and ended up repurposing Stellar to install Nvidia and Broadcom drivers if you connected to the internet during installation.

We decided pretty early in Readymade's design that the system should be configured on first-boot rather than in the installer, leading to us building Taidan.

## Pages

Taidan walks the user through, in order:

- Accessibility (screen reader, zoom, larger text, legible font)
- Language
- Keyboard layout, and the input method picker
- Welcome
- Theme (light/dark, accent color, and in the advanced dialog, the GRUB theme and Breeze Dark on Plasma)
- User account and password
- Time zone
- Network, including the device name and hostname, proxies, captive portals, and IEEE 802.1x
- Location services
- Analytics
- Drivers and codecs
- Tweaks
- Summary, install progress (with a log view), and a completion page

<Callout type="warning">
  The lists of keymaps and languages are generated at **compile time**!
  Keymaps are read from `/usr/share/X11/xkb/rules/evdev.lst` (`xkeyboard-config`) and
  locales from `localedef --list-archive` (`glibc-all-langpacks`).
</Callout>

## Running

Taidan runs on first boot when `/.unconfigured` or `/var/.unconfigured` exists. Two units ship with it:

- `taidan-initial-setup.service` starts a KWin Wayland session on tty7 as the unprivileged
  `taidan` user and runs Taidan in it.
- `taidan-initial-setup-reconfiguration.service` pulls in the above and holds back gettys and the
  display manager until setup is done.

Because of Fedora packaging limitations, Taidan doesn't ship a systemd preset. Your distro's presets need to
`enable taidan-initial-setup-reconfiguration.service`.

Logs go to the journal, specifically, `/var/log/taidan.stdout.log` and `/var/log/taidan.stderr.log`.

### Root helper

Everything Taidan does as root goes through `/usr/libexec/taidan-helper`. Taidan's polkit rule only allows
it to `pkexec` through the helper while the OOBE runs. The helper takes a fixed set of requests with
checked arguments, and once the system is marked configured, it refuses everything but a few cleanup
ones. You MUST install the helper binary while packaging Taidan:

```sh
cargo build --release -p libtaidan --bin taidan-helper
install -Dpm755 target/release/taidan-helper /usr/libexec/taidan-helper
```

<Callout type="warning">
  The helper limits what a bug in Taidan can do as root, but it isn't a boundary against other code
  running as `taidan`. NEVER allow untrusted code to run as the `taidan` user.
</Callout>

### Debugging

Boot with `taidan.debug_shell` on the kernel command line, then press
<kbd>Alt</kbd>+<kbd>Shift</kbd>+<kbd>T</kbd> for a root terminal.

When hacking on Taidan itself, `TAIDAN_LOG=trace cargo r` runs a simulated install. These
variables fake parts of it:

| Variable                         | Effect                                                         |
| -------------------------------- | -------------------------------------------------------------- |
| `TAIDAN_SIMULATE_HW`             | `nvidia`, `broadcom-wifi` (comma-separated) or `all`           |
| `TAIDAN_SIMULATE_ERROR=1`        | the install fails halfway                                      |
| `TAIDAN_SIMULATE_UPDATES=1`      | pretends updates were downloaded                               |
| `TAIDAN_SIMULATE_DRIVER_ERROR=1` | pretends the driver install failed                             |
| `TAIDAN_HELPER`                  | path to the root helper (debug builds only)                    |

## Configuration

Taidan reads an optional configuration file at `/etc/taidan.toml`. If it can't be parsed, Taidan
shows an error and uses the defaults.

```toml
edition = "plasma"                    # defaults to VARIANT_ID= in os-release
skip_pages = ["location", "drivers"]  # hide pages you don't want
org = "Fyra Labs"

[i18n]
imf = "fcitx5"                        # or "ibus". defaults to ibus on GNOME and fcitx5 elsewhere

[taidan0]
skip_dnf = false                      # never install packages with dnf
systemd_homed = false                 # create the user with systemd-homed
persist_no_internet_btn = false       # keep the "set up offline" button on the network page
```

The distro name comes from `NAME=` in `/etc/os-release` (or `/usr/lib/os-release`). Missing
`NAME=` falls back to `Linux` and missing `VARIANT_ID=` to an empty edition; it no longer panics as of v1.

The edition picks desktop-specific behavior: GNOME, Plasma (detected by `/usr/bin/plasmashell`),
Budgie, Xfce, or other. An `atomic-` prefix is ignored. Accent colors are only offered on GNOME and Plasma.

### Skipping pages

`skip_pages` takes these names (case-insensitive):

`accessibility`, `language`, `keyboard`, `welcome`, `theme`, `timezone`, `network` (or `internet`),
`location`, `analytics`, `drivers` (or `codecs`), `tweaks`, `inputmethod` (or `ims`).

Unknown names and pages that can't be skipped (account, password, summary and so on) are ignored with a warning.

- Skipping `keyboard` also hides the input method picker. Input methods are then picked from the
  locale. Skip `inputmethod` to set up none.
- Skipping `drivers` hides the page but still installs drivers and codecs.
- Skipping `network` keeps the system's hostname.
- Skipping `analytics` means the pageview is never sent.

### Branding

Other distros can replace Ultramarine's look from the same file. Every key is optional. Colors are
`#rrggbb` or `#aarrggbb`.

```toml
logo = "/usr/share/pixmaps/my-distro.svg"  # header and window icon
font = "Inter"                             # needs to be installed, Geist if unset
accent_color = "#00078f"                   # main buttons and selections, light mode
accent_color_dark = "#4a56e2"              # the same in dark mode
accent_foreground_color = "#ffffff"        # text and icons on the accent
accent_foreground_color_dark = "#ffffff"   # dark mode, accent_foreground_color if unset

[welcome]
t0 = "My Distro 42"                        # caption on the picture beside the pages, none if unset
t0_color = "#ffffff"                       # caption color
t1_color = "#ffffff"                       # Taidan version color, only shown in dev sessions
hero_image = "/usr/share/backgrounds/my-distro.png"       # the picture, light mode
hero_image_dark = "/usr/share/backgrounds/my-distro-dark.png"
```

The picture falls back to `/usr/share/backgrounds/default.png` (or `default-dark.png`), then to
Ultramarine's. The legible font option in the accessibility settings overrides `font` with Atkinson
Hyperlegible Next.

<Callout type="info">
  The GRUB theme option installs `ultramarine-grub-theme-{light,dark,darker}` with dnf and
  regenerates the GRUB config, so it's Ultramarine-specific. It's skipped when dnf can't be used.
</Callout>

### Analytics

If the user leaves analytics on, Taidan sends one [Plausible] pageview at the end of setup, with
`VERSION_ID=` and `VARIANT_ID=` from os-release, the CPU architecture, and whether the device is a
Chromebook, Surface or Raspberry Pi (from the `ultramarine-release-*` package). Nothing is sent
offline or when the `analytics` page is skipped.

### Runtime Fluent Loader

Fluent is the only supported i18n framework. Distributions may choose to provide custom translations
in `/usr/share/taidan/po/<lang>/taidan.ftl`. These translations are preferred over the compile-time
ones, which are only used when that directory can't be loaded.

### Tweaks

Taidan allows distributions to present "tweaks" as options to the user on the tweaks page. In
Ultramarine, we use them for things like offering the CachyOS kernel on capable hardware.

Tweaks are read at runtime. For the most up-to-date documentation, see `libtaidan/tweaks.rs`.

Tweaks MUST be stored in `TWEAKS_DIR`, i.e. `/usr/share/taidan/tweaks`. Here is an example
file hierarchy:

```
/usr/share/taidan/tweaks/ (TWEAKS_DIR)
┣╸my_tweak/
┃ ├╴tweak.toml (optional)
┃ ├╴condition (optional, MUST be executable)
┃ └╴up (required, MUST be executable)
┗╸other_tweak/
  ├╴tweak.toml
  └╴up
```

The ID of a tweak is determined by the directory name (`my_tweak`, `other_tweak`).

Every field of `tweak.toml` is optional:

- `ftl_name` (alias `name`): the fluent ID for the name of the tweak
  - fallback: `<id>-name`
- `ftl_desc` (alias `desc`): the fluent ID for the description of the tweak
  - fallback: `<id>-desc`
- `needs_internet`: `up` downloads something, so the tweak is skipped offline
- `needs_dnf`: `up` installs packages with dnf, so the tweak is hidden on atomic systems and with `taidan0.skip_dnf`

Unknown fields are an error. If the file can't be parsed the tweak is skipped, and if it doesn't
exist the fallback values are used.

Distributions SHOULD provide translations for their tweaks, see [Runtime Fluent Loader](#runtime-fluent-loader).

#### `condition`

The optional `condition` executable decides whether the tweak is offered on this system. It runs
unprivileged in the tweak's directory with no stdin, and must only inspect the system, not change
it. Exit code 0 offers the tweak. Any other exit code, failure to run, or a five-second timeout hides it.

It gets these environment variables:

- `TAIDAN_X86_64_LEVEL`: the x86-64 microarchitecture level (1–4), or 0 on other architectures
- `TAIDAN_SECURE_BOOT`: `0` for disabled, `1` for enforced, `unknown` if detection failed

```sh
#!/bin/sh
[ "${TAIDAN_X86_64_LEVEL:-0}" -ge 3 ] &&
	[ "${TAIDAN_SECURE_BOOT:-unknown}" = 0 ]
```

#### `up`

`up` runs as root. `up 1` turns the tweak on. `up 0` only runs when an earlier, unfinished install
turned it on and the user has since turned it off.

The user's choices (the `Settings` struct in `libtaidan/settings.rs`) are fed to it as JSON on stdin:

```jsonc
{
  "skipconfig": false,
  "nointernet": false,            // setting up offline
  "kb_layout": "us",
  "kb_variant": null,
  "device_name": "Cypress's Laptop",
  "hostname": "cypresss-laptop",
  "timezone": "America/Denver",   // "" to keep the system's
  "locale": "en_US.UTF-8",        // "" to keep the system's
  "fullname": "Cypress",
  "username": "cypress",
  "avatar": null,                 // path to the user's icon
  "install_codecs_drivers": true,
  "download_updates": true,
  "location": true,               // null when the location page was skipped
  "analytics": true,              // null when the analytics page was skipped
  "a11y": { "screen_reader": false, "zoom": false, "larger_text": false, ... },
  "dark_mode": true,              // null to keep the distro's default
  "accent": "blue",               // or teal, green, yellow, orange, red, pink, purple, slate, or null
  "proxy": null,                  // or { "url": "http://proxy:3128", "no_proxy": "localhost" }
  "proxy_persist": true,          // whether the installed system keeps using the proxy
  "ims": ["Pinyin"],
  "ims_picked": false,
  "imf": "fcitx5",                // or "ibus"
  "actions": [[], [], [], [], []],
  "tweaks": ["my_tweak"]          // ids of the tweaks to turn on
}
```
<Callout type="warning">
    The inforomation that Taidan passes to the `up` script should be treated as
    Personally Identifiable Information, and as such, you MUST ensure that any tweaks
    installed are vetted for security.
</Callout>

The proxy URL on stdin never has credentials in it. For its own downloads, `up` gets the full proxy
in `http_proxy` and friends. A tweak should only set the proxy up somewhere that outlives the
install when `proxy_persist` is `true`, otherwise Taidan removes its own proxy config.

<Callout type="info" title="Changes from the GTK version">
  - `langlocale` is now `locale`
  - `theme_is_dark` is now `dark_mode`, which can be `null`
  - `accent` is lowercase (`"blue"` instead of `"Blue"`)
  - `tweaks` is a list of the IDs to turn on instead of a `bool` per tweak
  - `passwd` is gone
  - `timezone`, `avatar`, `download_updates`, `location`, `analytics`, `a11y`, `proxy`, `proxy_persist`, `ims_picked` and `imf` are new
</Callout>

## Migrating from the GTK version

- `skip_pages = ["devicename"]` and `["crashreport"]` are ignored with a warning. The device name is on the network page now.
- `internet_timeout` and `internet_retry_interval` are ignored with a warning, and
  `/etc/com.fyralabs.Taidan/detect-internet` isn't run anymore. Connectivity comes from NetworkManager.
- `/usr/share/taidan/oobe.sh` isn't run anymore. Use a tweak instead.
- The analytics page now sends the Plausible pageview `detect-internet` used to send, only if the user leaves it on.
- Codecs follow the drivers toggle.
- The systemd preset is gone, see [Running](#running).
